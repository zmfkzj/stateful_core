검증 단계는 생략하고, 완료된 분석(영역별 정독 6개 + 비판 렌즈 6개 + 병합, 총 67건 → 중복 제거 57건)을 기반으로 보고합니다. 발견사항은 교차 검증 전이지만, 대부분 복수 에이전트가 독립적으로 보고했고 file:line 근거가 있으며, 일부는 실제 재현까지 된 것들입니다.

# stateful_core 점검 결과

## 한 줄 요약

**컨셉 자체는 실재하는 문제를 겨냥하지만, 문서가 약속한 것보다 훨씬 좁은 범위만 구현되어 있고, 그 좁은 범위 안에서도 "조정 레이어"가 스스로 동시성 결함(TOCTOU, 기아, 데드락)을 갖고 있습니다.** 가장 치명적인 것은 대표 시나리오(사람+에이전트 공존)가 구현 불가능한 상태라는 점과, 효과를 입증할 실증 데이터가 사실상 없다는 점입니다.

---

## 1. 컨셉 실효성 평가

**실제 구현된 것**: "협조적인 Codex 세션들 간의(agent↔agent) 사전 쓰기 조정". intent=범위 권한, lease=실시간 점유, queue=순서 있는 인계라는 모델 자체는 정합적입니다.

**그러나 컨셉의 두 기둥이 비어 있습니다:**

**① 사람 참여가 미구현 — 대표 시나리오가 작동 불가.** README의 간판 사례("사람이 README.md 편집 중 → 에이전트가 대기")를 성립시킬 메커니즘이 코드에 없습니다. 파일 워처도, authorize 시점 mtime/hash 비교도 없고, `HumanWriteObserved` 이벤트는 테이블만 존재하며(`stateful-store/src/lib.rs:2243`), 이를 위해 만들어진 OCC 메커니즘 `base_observations`는 **서버 쪽 검증 로직은 있는 데 프로덕션 호출자가 0개**입니다 — hook이 `/v1/authorize`에 절대 보내지 않습니다(`hook.rs:1205-1230`). 사람 쪽 보호 장치는 SKILL.md의 "편집 전에 다시 읽어라"라는 프롬프트 한 줄뿐입니다.

**② 실증 근거 부재.** 벤치마크 도구는 방대하지만(3.7k 라인), 디스크에 있는 유일한 실제 페어 실행은 **의도적으로 충돌 없는 페어에서 delta 0.000 + 벽시계 시간 ~31% 오버헤드**를 보여주고, 양(+)의 delta는 전부 생성기/스크립트가 하드코딩한 픽스처입니다. "충돌을 예방한다"는 핵심 가치 주장이 현재로선 증명되지 않았습니다.

**③ 대안과의 비교 논증이 없음.** 멀티에이전트 협업의 주류 해법은 격리(git worktree, 컨테이너, branch-per-agent)이고, 오케스트레이터 수준의 작업 분배는 애초에 겹침 자체를 막아줍니다. 문서 는 "공유 워크스페이스 니치"를 단언만 하고, 공유 트리가 *언제 꼭 필요한지*(거대한 node_modules/빌드 캐시, 단일 dev 서버/DB, 사람 IDE가 열려 있는 정본 체크아웃 등)를 정의하거나 측정하지 않 습니다.

**판정**: 컨셉이 유효한 조건은 명확합니다 — *동시에 활성인 장수명 협조 에이전트 세션 2개 이상 + 같은 repo + 실제 동일 파일/디렉토리 경합 + 턴 사이에 폴링하는 런타임*. 현재 설계는 이 조건 을 절반만 겨냥하고 있고, 마케팅(사람+에이전트)과 구현(에이전트+에이전트)이 어긋나 있습니다.

## 2. 구현 방법론의 문제 (정확성·동시성)

조정 레이어 본인의 동시성 결함이라 가중치가 큽니다. 단일 프로세스 내부는 `Arc<Mutex<Store>>`로 잘 직렬화되어 있지만, **경계에서 무너집니다:**

| 심각도            | 문제                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| critical          | **authorize→write TOCTOU**: allow 판정과 실제 파일 쓰기 사이에 펜싱이 없음. lease가 만료된 세션이 낡은 권한으로 계속 쓸 수 있음. 스펙(concurrency-control-spec.md:166-178)은 "write boundary: enforced"를 명시적으로 약속                        |
| critical          | **workspace_id가 정적 문자열**: 문서상 worktree 루트 해시여야 하는데 실제로는 `"local"`/`"shared"` 상수. 한 머신의 서로 다른 repo끼리 같은 상대경로로 가짜 충돌이 나 고, 반대로 호스트와 LAN 조인 세션은 같은 프로젝트에서 충돌이 영영 감지 안 됨 |
| critical          | **외부 쓰기 자가 승인**: Bash 게이트가 `external-run approve --run`을 허용해서, 시스템이 유일하게 만든 "사람 승인" 통제를 에이전트가 스스로 통과 가능 → repo 밖 임의 경로 쓰기                                                                   |
| major             | **하트비트가 모든 lease를 무한 연장**: 덮는 intent가 남아있는지 확인 없이 연장 → 문서의 "lease_expiry 승급"이 살아있는 세션에서는 절대 발화 못 함 → FIFO 대기자 기아, 서로의 파일에 큐잉한 두 세션은 ABBA 데드락                                 |
| major             | **예약 만료가 request_id를 영구 파괴**: 120초 풀(pull) 전용 알림 + 턴 기반 에이전트 → 예약을 놓치는 게 일상이 되고, 문서가 약속한 멱등 재시도로 복구 불가, FIFO 위치 소실                                                                        |
| major             | **SQLite 방법론**: PRAGMA 없음(WAL/busy_timeout), `Store::append` 밖은 비트랜잭션 다단계 전이(크래시 시 큐 대기자 영구 고립), 게다가 CLI가 라이브 서버의 DB를 직접 열어 파괴적 마이그레이션 실행 — "단일 작성자" 가정을 코드베이스 스스로 위반   |
| major             | **fail-closed가 실제로는 hook 크래시**: 서버 다운 시 deny를 출력하는 게 아니라 exit 1로 죽음 → fail-open/closed 결정이 러너의 hook 실패 의미론에 위임됨. 읽기 전용 sandbox 프로필조차 서버 없으면 동작 불가                                      |
| major             | **`--fs git`이 `.git` 전체를 쓰기 가능으로 마운트** + `git remote` 허용 → `.git/config`에 심으면 사람이 다음에 샌드박스 밖에서 git 쓸 때 실행되는 지속화 경로                                                                                    |
| critical (재현됨) | **빌드 샌드박스 프로필이 표준 툴체인을 깨뜨림**: `cargo build`가 Cargo.lock/`target/` 쓰기에서 "Operation not permitted" — SKILL.md의 공식 예제(SKILL.md:67)가 그대로 실패. `CARGO_TARGET_DIR=tmp/target` 우회가 필요한데 문서에 없음            |
| critical          | **intent replace 의미론이 자기 파괴적**: `tmp/` 빌드 intent를 선언하면 파일 intent가 날아가고, 그 반대도 마찬가지 → **문서가 권장하는 편집→테스트 루프의 두 단계가 서로를 무효화**                                                               |

참고로 Bash 명령 파서 자체는 견고하다는 평가입니다(외부 셸 문법 거부 + 미지 토큰 fail-closed + argv0 canonicalize) — 파서 우회 발견은 없었습니다.

## 3. 구조상 문제

1. **stateful-core가 빈 껍데기**: 문서상 "도메인 코어"인데 실제로는 intent 스코프 매칭만 있고, 진짜 정책 엔진은 stateful-server의 900라인 `PolicyService` + stateful-store의 raw SQL 중첩  판정에 있습니다. 둘은 이미 의미론적으로 갈라졌습니다(쓰기 인가는 깊이 ≤2, lease 차단은 무제한 깊이 — 어디에도 문서화 안 됨). 코어의 `PolicyState` 4차원 중 3개(phase/finalized/expired)는  스토어가 채우지 않아 **죽은 코드**입니다.

2. **어댑터 경계가 양방향으로 깨짐**: Bash 정책은 hook 어댑터에만 있고 서버는 Bash를 아예 못 보며, 반대로 서버 정책에는 `'apply_patch'|'Edit'|'Write'` 같은 에이전트 툴 이름이 하드코딩 —  프로젝트 자신의 "서버에 Codex 전용 가정 금지" 규칙 위반.

3. **"agent-runtime generic"이 구조적으로 거짓**: 추상화는 메서드 1개짜리 trait에 구현체 이름이 `ClaudeCodeRuntimeAdapter` 하나뿐이고, hook 스키마/설치/매처가 hook.rs·install.rs·서버에 흩어져 하드코딩 — 다른 런타임 채택은 사실상 포크.

4. **stateful-cli가 갓 크레이트(~10.6k 라인)**: hook 핫패스가 LAN, 벤치마크, 설치기와 같은 컴파일 단위를 공유하고, 벤치마크 배관이 프로덕션 PreToolUse 게이트에서 도달 가능.

5. **outbox가 스텁**: 정교한 at-least-once 재생 기계가 있는데 **서버가 payload를 버리면서 'synced'를 반환** — outbox가 존재하는 이유(가용성 저하 중 증거 보존)가 이벤트 로그에 도달하지 못 함.

6. **경로 정규화(충돌 도메인의 identity key)가 4군데 이상 중복 구현.**

7. **스펙↔구현 갭이 체계적**: 구현된 부분의 수치(모든 TTL, 깊이 규칙, envelope 5개 라우트)는 놀랄 만큼 정확하게 일치하지만, 문서 셋이 미래 목표를 현재형 규범으로 서술합니다 — 다중 리소스 원자 예약, warn 티어, conflicts 테이블, 14일 보존, `stateful init`, 감사 로그(이벤트 3종뿐, lease/큐/거부는 흔적 없음)가 전부 doc-only. LAN 조인은 선언된 non-goal인데도 평문 토큰으로 v1에 출하됨.

8. **테스트 전략의 공백**: 4.4k 라인 통합 테스트가 전부 순차 요청/응답 검증. 진짜 동시성 테스트, 크래시 중간 복구 테스트, 주입 가능한 시계가 전무(만료 테스트는 raw SQL로 타임스탬프를 변조).

## 4. 솔루션 (우선순위순)

**A. 컨셉 정렬 — 가장 먼저 결정할 것**
- 둘 중 하나를 선택: **(i)** 대표 시나리오를 agent↔agent로 재조준하고 사람-조정 마케팅을 구현 전까지 제거, 또는 **(ii)** 최소 사람-관찰 메커니즘 출하 — lease 획득 시 서버 측 mtime/hash 스냅샷, authorize 시 비교. 서버 쪽 `base_observations` 검증 로직(`policy_service.rs:462-507`)은 이미 있으므로 **hook이 그걸 보내게만 하면 됨** — 이 한 가지 배선이 TOCTOU(2번 섹션 critical) 와 사람-감지 문제를 동시에 절반 이상 해결합니다.
- exact_file_overlap 페어로 정직한 벤치마크 1회를 커밋하고, "예방한 충돌 수 vs 마찰 비용"을 수치로 제시.

**B. 동시성 핵심 수리**
- workspace_id를 문서대로 worktree 루트 해시에서 유도.
- intent를 additive(또는 merge) 의미론으로 변경 — replace 의미론은 자체 워크플로우를 깨는 footgun.
- 하트비트는 intent가 덮는 lease만, 상한선 내에서 연장. 백그라운드 만료/승급 태스크 도입(최소한 sweep을 단일 트랜잭션으로).
- 예약 만료 시 request_id를 죽이지 말고 재큐잉. 120초 claim 창을 턴 주기에 맞추거나 푸시 채널 추가.
- SQLite: WAL + busy_timeout 설정, 다단계 전이를 트랜잭션으로, DB 작성자를 서버 프로세스 하나로 강제(CLI 마이그레이션은 서버 경유).
- 서버 불능 시 hook이 구조화된 deny를 출력하게 수정(크래시 위임 금지). 읽기 전용 프로필은 서버 없이도 동작하게.

**C. 보안(자체 트러스트 모델 기준 위반만)**
- Bash 게이트에서 `external-run approve` 차단 — 승인은 대화형 TTY나 별도 채널로만.
- git 프로필에서 `.git/config`·hooks 쓰기 차단 또는 git 서브커맨드 필터 강화.
- 토큰 파일 0600, 세션 fallback의 last-writer-wins 제거.

**D. 구조 리팩토링 (재작성 아닌 경계 수리)**
- 충돌/lease 정책을 스냅샷 인터페이스 뒤의 stateful-core로 이동, 깊이 의미론 단일화.
- 경로 정규화 단일 함수/크레이트로 통합.
- stateful-cli 분리(최소 hook 핫패스 / 설치·LAN / 벤치마크 3분할), 벤치마크는 워크스페이스 분리 고려.
- outbox를 실제로 영속화하거나 삭제 — "synced 거짓말"이 최악.
- 문서에 state-model.md가 이미 쓰는 "shipped vs target" 상태 태그를 implementation-contract.md·current-state-coordination.md·architecture.md에 일괄 적용.

**E. 에이전트 사용성**
- 빌드 프로필이 실제 툴체인 캐시를 수용하게(`CARGO_TARGET_DIR` 자동 주입 등) — 현재는 공식 예제가 실패하는 상태.
- 거부 메시지에 queue→claim→resume 절차를 실패 시점에 가르치기(현재 hook이 wait_id를 버림, `hook.rs:1242-1247`).
- 컨텍스트 렌더러가 **자기 자신의 lease를 "Blocking: 대기하라"로 보고하는 버그** 수정 — 진짜 충돌 채널의 신뢰를 무너뜨림.
- 전면 Bash 거부 재고: 읽기 전용 명령 allowlist만으로도 첫 시도 실패율이 급감.
